# 心动模式（Folia 模组）

![心动模式](preview.jpg)

把网易云的**心动模式**接进 Folia：随机抽一首「我喜欢的音乐」当种子，接两首网易云心动推荐，
一组接一组无限循环；整条播放队列由模组接管，退出或重开 Folia 时自动还原你原来的队列。

不改应用、不覆盖安装，模组目录整个丢进 `mods/` 就行。

- 模组 id：`heartbeat-mode`　·　Folium 1　·　需要 Folia `>=0.7.18 <0.8.0`
- 权限：`net.fetch`　·　使用 `folium.internals`（面板会标「使用内部接口」）
- 需要登录网易云

## 装

**方式一：拖 zip。** 在 [Releases](../../releases) 里下载 `heartbeat-mode.zip`，打开 Folia →「模组」面板 → 拖进去。

**方式二：放目录。** 把这个仓库整个放到模组目录下（目录名随便，身份以 `mod.json` 的 `id` 为准）：

```sh
git clone <本仓库地址> ~/Library/Application\ Support/Folia/mods/heartbeat-mode
# Windows: %APPDATA%\Folia\mods\heartbeat-mode
```

然后启用它。首次启用会要求确认：本模组声明了 `folia` 版本范围并使用 `folium.internals`（宿主内部接口），
面板会标出「使用内部接口」，同意后才加载；权限确认里只有 `net.fetch`（经宿主的网络服务请求本机网易云后端）。

## 用

两个入口，做的是同一件事：

1. **进度条上的心动按钮**：播放器进度条右端的心跳图标。
   - 空闲：主题色，悬停「开启心动模式（网易云推荐）」。
   - 刚点下：立刻变成半透明的脉冲状态，`aria-busy`，悬停「正在准备心动模式（点击取消）」。这一步是同步画的，不等网络；等接口慢的时候不会再有「点了没反应」。
   - 已开启：强调色，悬停「退出心动模式（正在推荐）」。
   - 准备阶段再点一次＝取消，队列一个字都不会动。
2. **命令面板**（`Ctrl`/`⌘ + K`）搜 **心动模式**：
   - **开启心动模式**：立刻进入准备状态，然后按下面的规则接队列。
   - **退出心动模式**：把整条队列换回开启前的样子（从开启时那首的后面接起），正在放的那首留着。

一组的构成（开启时先接一组，之后自动续）：

```
正在播的歌 → [ 1 首随机的「我喜欢的音乐」→ 2 首网易云心动推荐 ] → 下一组 → … 无限循环
```

要点：

- **整条播放队列由模组接管**。开启时把你原来的队列存成快照，播放队列只留
  `[正在放的那首, 喜欢, 推荐, 推荐, 喜欢, 推荐, 推荐, …]`。队列里根本没有你原歌单的歌，
  所以「播完一组就顺着喜欢列表往下走」这件事在物理上不可能发生。
  - 之前是往你的队列里插歌：抽到的「喜欢」在你歌单里本来就有一份拷贝，同一个 key 在队列里出现两次，
    宿主切歌时用 `getPlaybackSongKey` + `findIndex` 定位当前歌，会命中靠前那份，下一首就回到原列表顺序——
    这就是「播完 1+2 又变成喜欢列表顺序」的根因。
- 退出（按钮 / 命令）时把快照换回来，并从开启时那首的**后面**接起；正在放的那首不打断。
  如果上次是直接把 Folia 关掉的，下次启动会把快照还原，不会让你的「我喜欢的音乐」只剩心动歌。
- 「我喜欢的音乐」是**整张歌单随机抽**的：每次在 0…(总数−50) 里随机取一页（每页 50 首），
  再打乱、去重后取一首。不是从列表头开始，也不会顺着列表往下走。
- 推荐走网易云心动模式的 `/playmode/intelligence/list`，**以这一组里那首「喜欢」为种子**，
  带 `count=2` 一次要两首；上游如果忽略 `count` 只回一首，就再要一次补第二首。
- **跑道**：当前歌后面始终保持 9 首心动歌（3 组）。每次切歌后不足就自动补；
  播过的老歌会被裁出队列（保留最近 8 首，让「上一首」还能回退）。
- **小歌单也能一直循环**：喜欢的歌整轮抽完、推荐的歌整轮用完，会重新放开再来一轮，
  不会放到一半就没歌可选。
- **同一时刻队列里绝不出现重复的歌**：宿主切歌靠 key 定位，重复就会错位，所以选歌时会避开队列里已有的 key。
- 推荐里已下架的会被挡掉；接口连续给不出新歌就停一分钟冷却，不空转。
- 你如果自己把整个队列换掉（换歌单、切音源），会话自动结束，不碰你的新队列。
- 个人 FM 模式下开启会自动切回普通队列，否则 FM 分支会绕开心动队列。

## 依赖与限制

- **需要登录网易云**。未登录会直接提示，不发请求。
- 心动推荐走本机内嵌后端的 `/playmode/intelligence/list`（你的 0.7.18 里已经有这条路由，已验证）。接口缺路由、被风控或给不出新歌时，自动退回**私人 FM** 续上，不会卡住。
- **用的是宿主内部接口**（`folium.internals` 的播放队列 store 与 `omni`），所以：清单钉了 `folia: ">=0.7.18 <0.8.0"`；Folia 升到 0.8 后宿主会拒绝加载这个模组，需要跟着更新。
- 心动推荐是**网易云服务端算的**，不是本模组自己的推荐算法：它参考你「我喜欢的音乐」整库和当前种子，强调种子那首、给相似风格，并把老喜欢和新发现混在一起（官方 2018 年对心动模式的说明）。本模组做的只是「随机抽一首喜欢 + 调这个接口要两首推荐」。
- **改装后要重启 Folia，或者连依赖的版本号一起改**：宿主给入口 `client.mjs` 的 URL 挂了 `?v=<内容摘要>` 做缓存失效，但相对导入（`./queue.mjs`、`./netease.mjs`）不继承这个查询串，同一个进程里热替换会拿到旧副本，报 `does not provide an export named ...`。本模组的这两个 import 已经自带 `?v=` 版本号，改装时记得一起改；不重启又忘了改，就重启一次 Folia。
- **播放器不能停在「单曲循环」**：宿主在单曲循环下由音频元素自己重放当前歌，不会走队列；模组拿不到那个开关（不在 `folium.internals` 里），切成列表循环或顺序播放即可。
- 只在主窗口可用；透明视频导出窗口里没有这些能力。
- 「正在播的歌」是必要条件：没有任何在播歌曲时会提示先播放一首（此时队列无从衔接）。

## 文件

| 文件 | 作用 |
| --- | --- |
| `mod.json` | 清单：id、client 入口、`net.fetch` 权限、`folia` 版本钉定 |
| `client.mjs` | 注册进度条按钮与两条命令；取种子、拉推荐、接管队列、维持跑道、退出/开机还原 |
| `netease.mjs` | 本机后端地址（`window.electron.getNeteasePort`）、会话 cookie（`localStorage`）、心动接口 |
| `queue.mjs` | 纯函数：播放 key（与宿主一致）、拼队列、补组、跑道计数、退出还原 |
| `test/harness.mjs` | 本地回路：用假的宿主与后端驱动真实代码，19 项断言（即时反馈、取消、接管队列、连播 30 首不掉回原列表、跑道、count 被忽略、FM 兜底、去重、退出/开机还原） |

跑测试：

```sh
node test/harness.mjs
```

## 出问题怎么报

- 模组面板里展开本模组：`folium.log` 的 warn/error 会记在那里（接口不可用、取详情失败、私人 FM 兜底失败都会记）。
- 最需要确认的一条：开启后命令面板/队列里有没有出现推荐歌。若「推荐接口不可用」出现在日志里，说明后端这条路走不通，此时走的是私人 FM 兜底。
